# 需求

面向 HarmonyOS NEXT 的开源 Clash 客户端。界面用 ArkUI 原生，内核基于 mihomo（Clash Meta）。2026-10-25 起，以 FastClient 为信息架构和操作密度参考，按成熟手机工具应用组织仪表盘、代理和配置三页；参考任务与信息层级，不照搬画面。

目标设备：华为 Mate 70 Pro（PLR-AL00），HarmonyOS 7.0.0.109，API 26，arm64-v8a。

## 2026-10-25 本轮验收重点

- 首屏同时看见连接操作、网速、出站模式和运行配置；节点列表与订阅列表直接服务日常选择，避免用装饰性大卡占据主要空间。
- 浅色、深色、系统状态栏与手势区保持一致；添加配置的 Sheet 可以关闭，草稿和既有订阅不因页面切换丢失。
- 网速使用连续两次真实采样之间的实际间隔；首次采样、请求错误和计数重置不显示虚假的零速率。内核空闲时返回的 `connections: null` 表示真实零连接，累计值及连续采样的零速率仍应正常展示；请求失败明确显示统计暂不可用。统计在后台暂停，回前台先重新确认 VPN 状态。
- 测速和订阅下载期间仍可断开；运行配置与下次选择区分，同一订阅更新后明确待重连；迟到响应不能恢复旧会话数据。
- 搜索默认只显示顶栏图标，进入后自动弹系统键盘；关键词保留原始空格、忽略大小写，按字面量过滤全部组的成员。无结果组不显示标签，当前组失配时切到有效组；清空恢复全部组并保持最近有效组及搜索模式，不强制重弹键盘。首次 Back 收键盘，第二次 Back 或左箭头退出并清词，保留组。
- 最初 25 项检查没有搜索断言，“香港”6 节点的样本也不等于 FastClient 搜索一致性验收；用户追问后才通过实物对照复现并修正。状态、时序、统计及搜索检查先扩展为 32 项，再增加离线 10 项和测速反馈 2 项，当前 44 项通过；另有 15 项目录真实解析与 strict TypeScript 检查通过。旧通知版的 18 项生命周期/通知专项仅作历史记录，不能算当前版通过。均为本机可控依赖/解析检查，真机结果单独记录。
- 搜索验收版本 HAP 已编译签名并通过 USB 覆盖安装，原订阅保留；该轮安装中断连接后已恢复本应用 VPN，`vpn-tun` 为 `172.19.0.1`。已退出搜索并恢复手动组“示例策略组”、选中“示例节点A”，保持该轮进入前的 VPN 运行状态；配置添加 Sheet 的 Back 关闭也已真机核对。未逐个测试 47 个节点，未重新验证成功导入/更新全路径，未进行大文件吞吐或长时间稳定性测试。

## 2026-10-25 后续：移除普通 VPN 连接通知

- 用户确认普通通知没有意义后，连接流程不再申请通知权限；扩展不发布、撤销连接通知，IPC 状态不再携带通知错误。连接状态仍由仪表盘和实际 TUN 状态反映。
- 曾在 API 26 真机同时开启 `isOngoing` 与 `isUnremovable`，通知仍能左滑删除而 VPN 保持运行。证据为 `/tmp/vpn-probe-flags.jpeg` 与 `/tmp/vpn-probe-swipe.jpeg`。这解释了放弃普通通知的原因，不作为当前版本功能。
- [华为状态栏说明](https://consumer.huawei.com/cn/support/content/zh-cn16115724/)提供系统 VPN 图标开关，连接时可由系统显示；它不是 HarmonyClash 应用图标。应用图标需要通知才会进入状态栏，无法单独显示而隐藏通知卡片。
- 用户此前的不可划走要求因公开 SDK 限制未实现；现已撤回通知需求，不再保留临时消息来替代常驻功能。

### 历史试验记录
- 初版 HAP 已编译并覆盖安装；真机确认首次授权允许后显示单条通知，点击回应用后保留，断开后 TUN 消失且通知撤销，再次连接不重复授权、退桌面后仍单条通知，`vpn-tun` 为 `172.19.0.1`。
- 生命周期已改为启停串行队列与入口代数失效，停止立即关闭转发；迟到的 setup/create 必须清理，系统 VPN 销毁失败保留资源标记并阻止新建越过清理屏障。当时含通知的去重测速反馈源码通过 18 项生命周期/通知专项；当前去通知源码的 44 项状态检查通过，均为读取真实源码、注入可控依赖的本机模拟，不是手机运行结果。
- 离线目录版本 HAP 已构建并 USB 覆盖安装，原订阅保留。真机连接后显示新图标的单条“VPN 已连接”，点击打开仪表盘；断开后 `vpn-tun` 不存在且通知撤销，再次连接恢复 3 个真实运行组（含 GLOBAL）、“示例节点A”当前选择及测速入口。证据为 `/tmp/final-connected-notification.jpeg`、`/tmp/final-notification-return.json`、`/tmp/final-stopped-notification.jpeg`、`/tmp/final-online-nodes.jpeg`。拒绝授权、类别关闭及启动失败等未操作分支继续标未测。随后去除测速完成提示的最终版亦已构建回装并真机核对；收尾保留当时的“示例节点B”选择及已开启 VPN，未主动改回此前节点。
- 公开替代能力也不能直接保证强常驻：长时任务仅支持 UIAbility 申请，用户删除通知会终止任务，`DATA_TRANSFER` 有真实上传下载及进度要求；LiveViewKit 需权益或联调白名单，且用户可删除实况窗。明确禁止删除的 `isRemoveAllowed` 是需 `ohos.permission.SET_UNREMOVABLE_NOTIFICATION` 的系统接口，当前普通应用不能使用。依据见开发指南的官方链接。

## 2026-10-25 回装结果：仪表盘、图标与离线目录

- 正常连接和断开只更新连接卡状态，不再额外显示重复的成功/断开 notice；实际连接失败等异常仍保留提示。网速尚无真实趋势时不显示解释占位文字或空白图框，未知数值仍显示 `—`，不补假速率。最终离线仪表盘截图 `/tmp/offline-final-dashboard.jpeg` 已确认提示和占位清理。
- `/tmp/harmonyclash-final-icon.jpeg` 真机桌面大文件夹已显示最终纯底双环图标；此前通知版也曾使用该图标，现普通通知已移除。
- `/tmp/offline-nodes.jpeg` 显示未连接时本地 47 个组成员、2 个 YAML 真实组，不合成 GLOBAL，不显示使用中和测速入口；`ifconfig vpn-tun` 为 `No such device`。`/tmp/offline-cdn.jpeg` 的 CDN 忽略大小写命中 3 卡，`/tmp/offline-hongkong-switch.jpeg` 的“香港”命中 6 卡且切至自动组仍保词，检查期间始终无 TUN。中文输入通过系统输入法输入 `xianggang` 后选择“香港”候选；首次 HDC Unicode 未正确输入不计为通过或失败样本。提供者/坏 YAML 等边界有本机检查覆盖，未全部真机操作。
- 用户再次指出“测速完成”的提示没有意义，单节点和整组成功均只更新卡片延迟，开始阶段仅保留按钮状态，不保留重复进度或成功提示；真正错误仍就地反馈。最终版构建日志为 `/tmp/harmonyclash-speed-clean-build.log`，已覆盖安装；`/tmp/speed-clean-single.json` 确认单节点 108 ms 且无完成/进度块，`/tmp/speed-clean-group-busy.jpeg` 仅按钮显示“测速中…”，`/tmp/speed-clean-group.json` 及同名截图确认当前香港 6 卡为 110/117/100/98/229/750 ms、无完成提示。整组样本仅确认当时可见的 6 卡，未核对全部 47 个节点的测速或连通性。2 项新增状态检查覆盖单节点/整组成功无反馈和失败保留错误；修改前 `/tmp/final-online-speed.json` 的“示例节点A”101 ms 与完成提示并存只作为旧版反证。
- 收尾已退出搜索并清词、返回仪表盘，保留当时“示例节点B”选择和开启的 VPN；`/tmp/final-speed-clean-dashboard.jpeg` 显示已连接、真实速度与累计且无冗余 notice，`vpn-tun` 再次确认为 `172.19.0.1`、`UP RUNNING`。未更新或删除原订阅。
